# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Windows-only speech-to-text tray app (Python 3.10–3.12, PySide6/Qt + pynput; `pyside6-essentials` only, trimmed further in the spec). Caps Lock toggles recording; audio is transcribed by a configurable STT provider and pasted at the cursor. Two "conversation modes" (Meeting/Phone) capture multi-speaker sessions with speaker-separated transcripts (see `docs/conversation-modes.md`).

## Commands

```powershell
# Environment: pyproject.toml + uv.lock are the source of truth (dev group included by default)
uv sync                                    # after editing pyproject.toml: uv lock, then uv sync

# Run (console, with logs visible)
.\.venv\Scripts\python.exe .\voice_typing.pyw --debug
# Run detached (source users)
.\run_voice_typing.bat

# Quick syntax check of edited files
.\.venv\Scripts\python.exe -m py_compile voice_typing.pyw modules\*.py services\*.py

# Unit tests (pytest config lives in pyproject.toml; see tests/README.md for what belongs there)
uv run pytest

# Frozen build + installer (what users get; CI does this on a v* tag)
uv run pyinstaller BetterVoiceTyping.spec --noconfirm        # -> dist\BetterVoiceTyping\
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" /DAppVersion=1.0.0 installer\BetterVoiceTyping.iss   # -> dist\installer\  (PowerShell only: Git Bash turns /Q and /D switches into paths and ISCC silently compiles nothing)

# Manual tool: real-keyboard hotkey check
.\.venv\Scripts\python.exe tests\manual\keyboard_test.py
```

Only one app instance can run (named mutex in `modules/single_instance.py`), so a frozen build and the dev instance can't run at once, and the installer aborts with exit code 1 while any instance holds the mutex. To find the holder, filter `Get-CimInstance Win32_Process` on `CommandLine -like '*voice_typing.pyw*'` or `Name -eq 'BetterVoiceTyping.exe'` — never kill by interpreter path (uv's `python.exe` is shared with every other uv-run tool on the machine, MCP servers included). The `.venv\Scripts\pythonw.exe` shim plus the real interpreter appear as two `pythonw` processes for one instance — not a duplicate. Installing the built setup with `/VERYSILENT /CURRENTUSER /MERGETASKS=!startup,!desktopicon` and uninstalling with `unins000.exe /VERYSILENT` leaves the machine as it was (user data is never touched); `/VERYSILENT` skips the post-install launch, so start the exe yourself.

Tests cover only brittle, load-bearing contracts (hotkey message sequences, chunk ordering/retry/cancel, error classification, `.env` editing) — no coverage target. Hardware, network, Qt widgets, and the global keyboard hook are never touched; if a change can't be tested without patching internals, add an injectable seam (clock, delay, callable) instead.

## Verifying changes

The unit tests deliberately leave the UI, audio and paste path alone, so every change that touches them gets checked live, in this order:

1. `uv run pytest`, then start the dev instance with `--debug`, redirecting its output to a scratch file (`... --debug > <scratch>\app.log 2>&1 &`) and read that log after each action — a crash in a background thread (e.g. the stop path) shows up only there. Restart it after every code change.
2. Drive the UI with Windows-MCP (see the global CLAUDE.md for its rules): `DisplayInventory`, then screenshots of display 0 only; right-click the tray icon (find it with a screenshot, it sits near the clock) to check the menu; left-click it to open the main window and walk the pages. Injected keystrokes are ignored by the hotkey **by design** (`LLKHF_INJECTED`), so Caps Lock can't be pressed for you: exercise the recording pipeline with the setup wizard's *Start recording* button (Home → Run setup again → step 3) and watch the pill, the tray colour and the log. Windows-MCP takes over the real mouse — say so before starting, and stop driving while the user is typing/dictating.
3. Indicator states without a screen: instantiate `UIFeedback` + `StatusManager` in a small script, push statuses/warnings, save `indicator.grab()` PNGs and read them (the session used `ui_demo.py` in the scratchpad for this).
4. Before a release or at the end of a multi-commit change: `/codex-review` on the range (`git diff <base>..HEAD`) at the default effort; `xhigh` only for architecture-level work. Triage per the skill (act on concrete bugs, note trade-offs, drop generic advice) and fix before tagging.
5. Frozen build smoke: `uv run pyinstaller …`, ISCC from PowerShell, silent install, launch the exe, check `Documents\VoiceTyping\logs\voice_typing_<date>.log` for "Tray icon started" and no traceback, then repeat the tray/window walk on the installed copy.

## Architecture

`voice_typing.pyw` owns the `VoiceTypingApp` orchestration: hotkey listener, recording lifecycle, the recorder side of conversation sessions (`_flush_chunk` / `_end_session`: sealing chunks, restarting capture, salvaging the tail), a 100ms main-thread watchdog (`_check_recorder_status`, scheduled via `UIFeedback.after`), and the processing pipeline (analyze → transcribe → optional LLM clean → paste). Everything else is a module with one job:

- `modules/session.py` — `ConversationSession` (one meeting/phone session: its `ChunkQueue`, preamble, failure summary, delivery callbacks) talks to the app only through the `SessionHost` protocol, which `VoiceTypingApp` implements (`is_current`, `deliver_text`, `show_failure`, …). `SessionNotes` is the indicator's state/alert note machine (app-level, `self._notes`). `build_preamble` is pure settings → text. All three are tested with fakes.

- `modules/hotkey.py` — `CapsLockHotkey`: pure state machine turning raw keyboard-hook messages (auto-repeat, Ctrl+Caps chord, injected keystrokes, lost key-ups) into one `TOGGLE` per physical press. The pynput `win32_event_filter` in `voice_typing.pyw` is a thin adapter over it; put new hotkey rules here with a test, never in the adapter.
- `modules/recorder.py` — `AudioRecorder`: mic capture thread writing `temp_audio.wav`. Flags consumed by the watchdog: `auto_stopped` (initial silence), `error` (device/stream failure — callers must keep captured audio), `max_duration_reached`. Meeting mode adds `modules/loopback_recorder.py` (WASAPI system-audio capture via `soundcard`), composed into a 2-channel WAV on stop.
- `modules/audio_level.py` — the single place that judges loudness, used by `AudioRecorder.analyze_recording`, the mid-recording warning and the settings-window mic test. It is an **energy detector, not a VAD**: it cannot tell speech from hiss and does not try. Two decisions are kept apart: `has_signal` (worth transcribing — rejects only a dead stream, because discarding a real dictation costs far more than a wasted API call *or* a bogus paste) and `speech_db`/`verdict` (how loud, which only ever drives advice). `speech_db` is the RMS of the loudest fifth of the frames above `SILENCE_FLOOR_DB`, so *silent* pauses cannot move it — the old whole-file mean RMS counted pauses as signal and threw away long dictations. A noisy room still can, which softens advice only. `analyze_blocks` + `frame_length` let a long file be analyzed without decoding it whole. `LiveLevelTracker` is the rolling version fed from the audio callback. Put any new level judgement here, with a test.
  Because rejection is deliberately permissive, **everything downstream must tolerate an empty or nonsense transcript**: `_attempt_transcription` treats blank/whitespace as empty *before* LLM cleaning, and `ConversationSession._on_result` never pastes or deletes a blank chunk. Two thresholds are load-bearing and coupled: the recorder clamps `silence_threshold` (the live silent-start auto-stop) to `SILENCE_FLOOR_RMS`, because that auto-stop fires before any analysis and keeps no retry candidate — a higher value silently destroys quiet speech, which is exactly what the old -40 dB default did.
- `modules/endpoint_volume.py` — the Windows *input volume* of the recording device (Settings → Sound → device → Input volume), read via pycaw/COM once per recording on its own thread (`check_async`; COM is per-thread) and shown on the indicator as "Windows mic volume is 42%" / "mic is muted". It exists because meeting apps' mic auto-gain keeps lowering that setting (24%, 24%, 42% on Dimitri's machine) and the level bands in `audio_level.py` cannot catch a 13 dB attenuation without nagging every soft-spoken user; this checks the cause instead of the symptom. `match_endpoint` (MME-truncated PortAudio name → endpoint friendly name, ambiguous = None) and `volume_note` are pure and tested; the COM read never raises. **COM rules learned from the 1.0.2 crash** (access violation in `_ctypes.pyd`, twice, hours after release): get interfaces with `iface.QueryInterface(IAudioEndpointVolume)`, never comtypes/ctypes `cast` (no AddRef → double Release from the GC on a random thread later), and do all COM on the module's one persistent thread (`_ComWorker`) whose apartment is never torn down. `tests/test_endpoint_volume_com.py` pins both with fakes.
- `modules/transcribe.py` — provider router. Recordings self-describe via `modules/audio_markers.py` (`recording_kind`: 2 channels = meeting, WAV comment `voice_typing:phone` = phone; markers survive snapshots/retries/restarts); otherwise dictation via `stt_provider` setting, where `null` = auto (ElevenLabs if `ELEVENLABS_API_KEY` is set, else OpenAI). The `custom` provider is `OpenAITranscriber` pointed at an OpenAI-compatible base URL (`services/custom_stt.py`). Transcriber instances in `services/` are cached by full config tuple; provider SDK imports are lazy for startup speed.
- `modules/clean_text.py` — optional LLM cleanup of dictation via the OpenAI chat API (`llm_model`, optional `llm_base_url` for compatible servers). Any failure falls back to the raw transcript.
- `modules/chunk_queue.py` — `ChunkQueue`: session chunks transcribe concurrently but deliver strictly in order at the cursor; one auto-retry, then the file is kept for tray retry. Lock order is documented in the file (delivery lock → state lock); callbacks fire outside the state lock. `retry_delay` is injectable for tests.
- `modules/settings.py` — `Settings` singleton; also loads API keys at import from `Documents\VoiceTyping\.env` (moved there from the app folder on first 1.0 run; it overrides same-named machine environment variables, and the app-folder `.env` is still read as a non-overriding fallback). The settings window edits that file in place through `modules/env_file.py`. Load order: raw JSON → `modules/settings_migrations.py` (`migrate`: pure, versioned by `schema_version`, tested with fixture dicts; add a new version there for any schema change) → merge defaults → `_reconcile_devices` (runtime hardware matching, reruns every launch, never a migration). Settings and history are written through `modules/fileutil.py` (`write_json_atomic`: temp file + fsync + `os.replace`, previous version kept as `.bak`; `read_json_with_backup` recovers from the `.bak`). Never write user JSON with a bare `open(..., 'w')`.
- `modules/ui.py` + `modules/status_manager.py` + `modules/tray.py` — Qt. `UIFeedback` owns the `QApplication` and one frameless translucent `IndicatorWindow` per display (fixed width measured from the widest status text so the elapsed timer never resizes it; the level bar doubles as an indeterminate sweep while transcribing). Qt widgets are main-thread only: every public `UIFeedback` method is thread-safe (inline on the main thread, else posted through a queued signal); use `UIFeedback.after(ms, fn)` for delayed work and `call_on_main` to hop threads. Mid-recording warnings must use `set_recording_note`, not `show_warning` — the elapsed-time ticker repaints the label. Always-on-top is re-asserted with `SetWindowPos(HWND_TOPMOST)` on every show and every pulse tick because Windows demotes topmost windows and Qt sets the flag only once. When reporting a retryable error, call `status_manager.set_status(ERROR, …)` *before* `show_error_with_retry(…)`: only the notice carries the hint and the "click to retry" line. The tray is a `QSystemTrayIcon` whose menu is rendered from a pure `MenuItem` tree (`build_tray_menu`) on every open, and whose glyph is painted at the current status colour (`tray_color`); Qt handles Explorer restarts itself.
- `modules/main_window.py` — `MainWindow` (sidebar: Home, History, General, Dictation, Conversation, Indicator, Advanced) and `SetupWizard` (keys → microphone → try it; finishing stores `setup_completed`). Controls write straight to `Settings` and apply live through the app's existing methods (`set_microphone`, `toggle_*`, `transcribe.set_stt_provider`, `UIFeedback` setters) so the tray and the window can't disagree. Created lazily by `VoiceTypingApp.show_main_window(setup=…)`; closing hides. Helpers: `modules/env_file.py` (in-place `.env` edits + `validate_key`), `modules/mic_test.py` (`MicMonitor`: its own short input stream and a plain-language verdict), `modules/startup.py` (Startup-folder shortcut, frozen builds only), `modules/sounds.py` (numpy-synthesized start/stop cues via winsound behind the hidden `sounds_enabled` setting — not in the UI because output-device start-up latency swallowed the clips in testing).
- `modules/paste.py` — the one delivery strategy: clipboard + Ctrl+V (pynput) + delayed clipboard restore, serialized by a lock. The pre-1.0 output-provider plugin system is gone by decision; don't reintroduce a plugin folder.
- `services/openai_realtime_stt.py` — streaming dictation (beta) over an OpenAI Realtime websocket while recording; any failure falls back to the batch upload (the WAV is always written in parallel).
- `modules/tray_pin.py` — promotes the tray icon out of the Windows 11 overflow by setting `IsPromoted=1` on the `HKCU\Control Panel\NotifyIconSettings` entry whose `ExecutablePath` is ours (identity is the exe path, so each install starts hidden). The app does it once per executable (`tray_pinned_exe` setting) shortly after startup, with retries while Explorer registers the icon.
- `modules/paths.py` — every path comes from here: `APP_DIR` (bundled resources; `sys._MEIPASS` when frozen), `INSTALL_DIR`, `USER_DATA_DIR` (`Documents\VoiceTyping`: settings, `.env`, history, logs), `LOCAL_DATA_DIR` (`%LOCALAPPDATA%\BetterVoiceTyping`: in-progress recordings, update downloads), `app_version()` from the bundled `version.txt`.
- `modules/updater.py` — installer-based self-update for frozen builds only: GitHub latest release → `BetterVoiceTyping-Setup-<v>.exe` asset verified against `SHA256SUMS.txt` → helper script (`cmd.exe` started with `CREATE_NO_WINDOW`, **never** `DETACHED_PROCESS`: without a console the helper's `tasklist | find` pipeline hangs in a flashing terminal window and the installer never runs, which is how the first real update failed) waits for our PID, runs setup `/VERYSILENT`, relaunches. On the next launch `_announce_update` shows "Updated to vX" (keyed on the `last_run_version` setting). Source checkouts get the releases page. Never overwrite the program folder from inside the app.

`VoiceTypingApp._update_level_note` runs off the same 100ms watchdog and puts a quiet/silent-mic warning on the indicator *during* recording. The Windows input-volume reading (`_endpoint_reading`, filled asynchronously by `_check_input_volume` at recording start, generation-tagged so a late read can't describe the next recording) outranks the level verdicts in that note, because a low or muted endpoint is the cause of whatever the level looks like. It uses `SessionNotes.set_warning`, the sticky middle layer (alert > warning > state): never `show_warning` (the elapsed ticker repaints over notices) and never `set_state` (a session's queue count lives there, and the two would erase each other). Every rejected *dictation* — including a silent-start auto-stop, which now seals its audio instead of discarding it — is reported with `show_error_with_retry`, because the audio survives in `last_recording` and `retry_transcription` bypasses the check entirely. Session chunks are the exception: a too-short or no-signal chunk is still deleted by `_flush_chunk` (only analysis *errors* are kept), since a session flushes constantly and every chunk cannot be a retry candidate. `analyze_recording` failures that mean *could not read the file* are prefixed `ANALYSIS_ERROR_PREFIX` so `_flush_chunk` keeps that chunk instead of deleting it as an empty one.

Concurrency invariants in `voice_typing.pyw`: recording start/stop/flush are serialized by `_toggle_lock`; the processing pipeline takes its recording path as an argument (`process_audio(recording_path=…)`) rather than reading `self.last_recording`, which a session callback can overwrite in the window before the worker thread is alive — that race transcribed and pasted the wrong recording's audio; `_recording_generation` stamps snapshot filenames (`temp_audio.wav.N.wav`) so a new recording can't clobber one mid-transcription; `_watchdog_token` ties the poll chain to the recording that started it. The snapshot sweeper must never delete files still referenced by a live session (the `_recent_sessions` registry, filtered by `ConversationSession.active_paths()`).

User data (settings.json, `.env`, logs, history.json) lives in `Documents\VoiceTyping\` and in-progress recordings in `%LOCALAPPDATA%\BetterVoiceTyping\recordings\`, never in the program folder — the installer replaces it wholesale.

pynput gotcha: `listener.suppress_event()` raises an exception by design — code after it never runs (documented where used in `voice_typing.pyw`).

## Conventions

- Type hints on all function parameters and return values.
- No blocking operations on the Qt main thread (network calls from the settings window go through a worker thread and report back via a signal).
- Comments: preserve nearby `NOTE:`/`IMPORTANT:` comments when editing code around them.

## Changelog

`CHANGELOG.json` is the changelog of record (README links to it). When updating: check for an existing entry with the same category and today's date — append to its `changes` array if found, otherwise create a new object at the top of the `changelog` array. Each object requires `category`, `date` (YYYY-MM-DD), and a `changes` array of descriptive, full-sentence strings written for end users. Use the `General` category unless a better one exists. Entries that ship in a release also get a `version` field.

## Release process

1. Bump `version.txt` AND `pyproject.toml` (bare number, e.g. `1.0.0`; `tests/test_version.py` checks they match) and give the `CHANGELOG.json` entry that `version`.
2. Commit and push to `master`; CI (`.github/workflows/ci.yml`) runs tests and a PyInstaller build.
3. Tag and push: `git tag vX.Y.Z && git push origin vX.Y.Z`. The Release workflow refuses a tag that doesn't match `version.txt`, then builds the installer, writes `SHA256SUMS.txt`, and publishes the GitHub Release with notes from `scripts/release_notes.py`.
4. Smoke-test the installer per `docs/release-checklist.md`. Installed apps pick the release up via the daily check / tray "Check for Updates".

The installer is unsigned (documented in README: users click "More info → Run anyway"). Revisit Azure Artifact Signing (~$10/month, individual identity validation) once download counts justify it.
